## Technical Decisions

### Decision 1: Category Organization
**Rationale:** Organize by component purpose/role rather than by feature
- Easier to find components
- Promotes reusability
- Clearer separation of concerns
- Aligns with industry standards (Atomic Design principles)

### Decision 2: Barrel Exports
**Rationale:** Enable clean imports and future tree-shaking
- `import { Button } from '@/components/ui'` vs `import Button from '@/components/ui/Button'`
- Easier refactoring
- Better IDE autocomplete
- Explicit public API

### Decision 3: Error Boundaries Stay in Root
**Rationale:** Cross-cutting concern, not a standard component category
- Used across all categories
- Special lifecycle requirements
- Higher-order components
- Not part of normal component hierarchy

### Decision 4: Keep auth/ and study/ Separate
**Rationale:** Already well-organized, domain-specific
- Auth is a complete module
- Study mode is a feature vertical
- No benefit to forcing into categories
- Maintains existing organization
